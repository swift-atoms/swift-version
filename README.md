# swift-version

Use this package to compare, constrain, bump, parse or print version numbers. Start from `Version.Semantic` for SemVer 2.0.0 versions, `Version.Tools` for `major.minor[.patch]` toolchain versions, and `Version.Calendar` for CalVer versions. Use `Version.Range` for one interval and `Version.Set` for any set of versions that intervals and exact versions can describe.

## Laws

- `Version.Semantic` equality and hashing ignore build metadata. Ordering compares major, minor and patch numerically. A version with pre-release identifiers sorts before the same version without them. Pre-release identifiers are compared one at a time: a numeric identifier sorts before an alphanumeric one, numbers compare by value and text compares lexically. When one list is a prefix of the other, the shorter list sorts first.
- `Version.Semantic.phase` is `.initial` exactly when major is 0, whatever the pre-release identifiers say.
- `Version.Semantic.bumped` increments one component, sets the components below it to 0, and drops all pre-release and build metadata identifiers.
- `Version.Range.upToNextMajor(from:)` and `Version.Range.upToNextMinor(from:)` include their start and exclude the next major or minor release. The next release has no pre-release identifiers.
- `Version.Tools` keeps an omitted patch distinct from an explicit 0 when printed: `6.4` stays `6.4`. Ordering treats a missing patch as 0, and on a tie the form without a patch sorts first, so `6.4` < `6.4.0`. This ordering agrees with equality.
- `Version.Calendar` ordering compares year, then month, then micro, treating a missing component as 0. On a tie, the less precise form sorts first: year only, then year and month, then all three, so `2026.05` < `2026.05.0`. On a further tie, a version with a modifier sorts before one without, and modifiers compare lexically. This ordering agrees with equality.
- `Version.Calendar.description` pads month and micro to two digits, so `2026.5` prints as `2026.05`.
- `Version.Calendar(parsing:)` rejects non-ASCII input and anything after the version. It rejects a month outside 1 to 12, a year or month that does not fit `Swift.Int`, and a micro that does not fit `Swift.UInt`. A modifier follows `-`, must be non-empty, and may contain only ASCII letters, digits and `-`. Leading zeros are accepted. `Version.Calendar.Parser` itself does not reject trailing input.
- The serializers write `description` bytes and append to the buffer without clearing it. A `Version.Calendar` built in code with a negative year or a non-ASCII modifier serializes, but that text does not parse back.
- `Version.Semantic.Parser` and `Version.Tools.Parser` read greedily and leave anything after the version core in the input. Pre-release and build metadata identifiers, however, run to the next `.` or `+`, so a foreign byte inside them is an error rather than a stopping point. Core numbers and numeric pre-release identifiers reject leading zeros, and every number rejects `Swift.UInt` overflow. Error ranges are byte offsets counted from where parsing started. A missing core component reports an empty range at the position where it was expected.
- `Version.Range` treats its bounds as points on a dense order. It is empty when the lower bound exceeds the upper, or when they are equal and either bound is exclusive. `Version.Range.intersection(_:)` always returns a range, which may be empty. An empty range is a subset of every range. `Version.Range.contains(_:)` given a range means subset. Range equality is structural, so two empty ranges with different bounds are unequal.
- `Version.Set` equality is structural, so compare `normalized()` forms. `Version.Set.normalized()` drops empty members, including empty ranges, and flattens nested unions. A union containing `.any` collapses to `.any`, a union of no members becomes `.empty`, and a union of one member becomes that member. It does not remove duplicates or merge overlapping members. `Version.Set.union(_:)` and `Version.Set.intersection(_:)` return normalized sets, and intersection distributes over unions.
